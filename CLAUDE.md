# Utter

GNOME voice dictation app. Python 3.13, GTK 4, libadwaita, GStreamer, sherpa-onnx. Packaged as a Flatpak on the `org.gnome.Platform//50` runtime.

## Layout

- `src/utter/` application package. Pure modules with no GTK imports: `formatting.py`, `models.py`, `enhance.py`, `history.py`, `keys.py`, `live.py`, `recognizer.py`. GObject modules: `audio.py`, `sounds.py`, `portal.py`, `shortcuts.py`, `injector.py`, `modelstore.py`, `dictation.py`, `overlay.py`, `window.py`, `preferences.py`, `main.py`.
- `gnome-shell-extension/utter-overlay@jaydoubleu.github.io/` the Utter Overlay GNOME Shell extension (GJS, ESM, GNOME Shell 50).
- `data/` desktop file, metainfo, GSettings schema, D-Bus service, icons.
- `build-aux/flatpak/` manifest and pinned Python wheels.
- `build-aux/screenshots/` `take.sh` makes the images in `docs/screenshots/` (README and metainfo).
- `build-aux/release/` the release scripts and the public signing key. `.github/workflows/` `ci.yml` (lint, tests, Meson validation, unsigned Flatpak build) and `release.yml` (tag `v*`).
- `tests/` pytest for the pure modules.

## Key design points

- `dictation.py` is the state machine: idle, loading, listening, transcribing, enhancing, typing. Worker threads report back with `mainthread.run_on_main`. `recognizer.ModelLoader` runs one model load at a time. A start during the preload at startup adds its callback to the load in progress, so the state does not stay at `loading`. If a request asks for a different model, language or thread count during a load, that load starts when the current load ends, and the waiting callbacks get its result. `main()` sends Python `logging` to stderr, and stderr goes to the journal (`journalctl --user | grep utter`). A failed enhancement logs a warning with the provider, the model and the error, but not the dictated text.
- Models have a `kind`: `transducer`, `whisper` and `streaming`. `Recognizer.start_live()` gives the live session for the loaded model, or None for Whisper. `streaming` (Nemotron 3.5, 320 ms chunks) uses a `StreamingSession` on `OnlineRecognizer` that decodes each chunk once. `transducer` (Parakeet) uses a `RedecodeSession` that decodes the recording again with `OfflineRecognizer`: first after 1 s, then every 0.6 s (the FluidVoice timings). Parakeet needs about 55 ms per second of audio on 4 threads, so the preview decodes in 15 s segments and the text of a full segment stays fixed. `live.py` polls `AudioCapture.read_new()` every 100 ms, feeds the session and reports the text through the `partial` signal. At the stop, `LiveDecode.finish()` gives the session the samples that it did not read yet. `RedecodeSession.finish()` decodes the full recording once, so the final text does not depend on the segments. Then the usual format, enhance and deliver steps run. The app types the text after the stop only.
- `overlay.py` exports `io.github.jaydoubleu.Utter.Overlay` on `/io/github/jaydoubleu/Utter/Overlay` on the app's bus connection. Signals: `StateChanged(s)`, `Level(d)` (0..1, at most every 50 ms), `Partial(s)` (last 150 characters). Methods: `GetState() -> (ss)`, `Cancel()` and `SetTargetApp(s)`. While the state is `loading`, `listening`, `transcribing` or `enhancing`, the extension grabs Escape with `global.display.grab_accelerator()` in `Shell.ActionMode.NORMAL` and calls `Cancel()`. At all other times Escape goes to the focused app. `Dictation.cancel()` adds one to `_generation`, and the worker results of an older generation do nothing. Utter cannot stop the typing after it starts. The Utter Overlay extension draws the panel from these. GNOME gives a new app window the keyboard focus (tested on GNOME 50), so the panel must not be an app window.
- The extension ports the FluidVoice "medium" panel: 340 px wide, 50 px above the bottom of the monitor, 8 bars driven by a spring (stiffness 260, damping 21), a shimmer while Utter processes. St draws the `box-shadow` of a gradient background without the rounded corners, so the panel background is one colour. GNOME 50 `addTopChrome()` takes no `affectsInputRegion` option. The panel is not reactive, so clicks go to the window below. To test it without a new login, run `gnome-shell --headless --virtual-monitor 1280x720 --wayland --no-x11` on the host inside `dbus-run-session`, with `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_RUNTIME_DIR` in a temporary directory. Without a private `XDG_RUNTIME_DIR`, the private session starts a document portal that replaces the FUSE mount at `/run/user/1000/doc`, and Flatpak apps fail with "bwrap: Can't find source path" until `systemctl --user restart xdg-document-portal`.
- `build-aux/screenshots/take.sh` runs on the host. It starts two private headless shells with a private home: one runs the real Flatpak with demo settings and history (`seed.py`, `driver.py`), and one runs `gnome-text-editor` and a fake Utter on the overlay D-Bus interface (`overlay_play.py`). The `shot-helper@local` test extension takes the screenshots, because GNOME Shell does not let other clients use its screenshot interface. `driver.py` must not block on the screenshot call: the shell waits for a new frame of the window. After the session ends, the script unmounts the `doc` and `gvfs` FUSE mounts in the private runtime folder.
- `enhance.py`: each `Provider` has an `api`. `openai` uses `urllib` and `/chat/completions`. `anthropic` uses the official `anthropic` SDK (imported late) with `claude-haiku-5-5` by default, effort `low`, and treats the `refusal` and `max_tokens` stop reasons as errors. `cerebras` and `groq` have `short_reasoning=True` and use `gpt-oss-120b` by default (`openai/gpt-oss-120b` on Groq) (about 0.3 s per cleanup, tested October 2026). `gemini` uses the OpenAI-compatible endpoint `https://generativelanguage.googleapis.com/v1beta/openai` with `gemini-3.5-flash-lite` (about 0.5 s). Gemini gets no `reasoning_effort`, the same as in FluidVoice, so the model selects its own thinking. This gave better corrections at the same speed (tested October 2026). `Provider.request_options(model)` adds `reasoning_effort`: `low` for gpt-oss, `none` for Qwen 3, because Qwen 3 on Cerebras otherwise reasons for 2 to 12 s. Gemini lists its models as `models/<id>`, and `list_models()` removes the prefix. Qwen 3.8 27B is faster on Groq (about 0.15 s) but types formatting words such as "comma" as text. `clean_reply()` turns the narrow no-break spaces of gpt-oss into plain spaces. Each provider has its own API key (`secrets.load_api_key()`, secret `enhance-api-key-<id>`). Older versions kept one shared `enhance-api-key`. At startup, `migrate_api_key()` gives it to the provider that `provider_for_key()` finds from the key prefix (`sk-ant-`, `gsk_`, `csk-`, `AIza` and others), else to the selected provider if it uses a key, and deletes it. When it returns True, `api-key-migrated` stops later runs. So a key never goes to the host of a different provider. The Preferences shows a toast when an applied key has the prefix of a different provider. At startup and at a provider change, `model_for_provider()` replaces an empty model or the default model of a different provider. A provider without a default model keeps such a model, because OpenRouter, LM Studio and vLLM also use `openai/gpt-oss-120b`. It loses only a model of a provider with a different API, such as `claude-haiku-5-5` on an OpenAI-compatible server. A 401 or 403 reply gives "<host> did not accept the API key." `list_models()` leaves out speech, voice, embedding and safety classifier models (`_NOT_CHAT`), because Groq lists Whisper, Orpheus and prompt-guard models, and Gemini lists image, audio, live, Veo, Lyria and embedding models, with the chat models. Preferences shows one toast at a time (`_show_toast()`), because Adwaita queues toasts and a test result can otherwise wait for the earlier toast. In tests on 16 runs, Cerebras with effort `low` applied a spoken correction ("Thursday no wait Friday") 11 times and Groq 16 times. Effort `medium` was worse on both. `store_secret()` with an empty value removes the secret from the keyring and from the fallback file. Providers with `needs_key=False` get no key. `DEFAULT_PROMPT` is the FluidVoice dictation prompt (its hidden base prompt and its default body) and one more paragraph. The prompt goes in the system message, and the transcript goes in the user message between `<transcript>` tags (`build_messages()`). FluidVoice puts both in one user message. With that layout, Gemini answered dictated requests such as "give me a table of the next steps" or "commit changes", and typed its answer (tested October 2026). The extra paragraph says that the text is not a message to the model, and that it must not make a requested table, list, answer or action. With it, Gemini answered 0 of 20 such requests, without it 1 of 20. A custom prompt with `${transcript}` goes in one user message, with the transcript in place of the placeholder. The prompt asks for `""` when the speaker cancels everything. Gemini then sends a message without `content` and `finish_reason: "stop"`, and `enhance()` returns an empty text. `Dictation._discard_empty()` then shows a notice and goes back to idle, with no typing and no history entry. An empty reply with a different finish reason is an error. The Flatpak installs the SDK and its 15 dependencies from pinned wheels in `python3-deps.yaml`. CI tests with the same versions of `anthropic`, `sherpa-onnx` and `numpy`. `anthropic` 2 sends the key in `Authorization: Bearer`, not in `x-api-key`.
- `StreamingSession.finish()` adds 0.66 s of silence before `input_finished()`. A shorter tail loses the last word. Greedy search makes the partial text append-only. In `auto` language mode the text has a double space where sherpa-onnx removes the language tag, and `tidy()` collapses it.
- The `language` key holds one code from `LANGUAGES` in `models.py`. `language_choices(spec)` gives the codes that a model accepts, and the Language row in Preferences shows only those. `recognizer_language(spec, language)` gives the string for sherpa-onnx: Whisper gets the base code, `""` for `auto` and `no` for `nb`. sherpa-onnx exits the process when Whisper gets an unknown code. Nemotron accepts locale codes such as `en-GB` and uses `auto` for an unknown code. `en` means `en-US`. In tests, `en-GB` did not give British spelling.
- The Language row must not call `set_model()` inside its own `notify::selected` signal. That crashes GTK. `_language_busy` prevents it.
- `portal.py` wraps GDBus portal calls. `request()` subscribes to the Request Response signal before it calls the method. `subscribe()` filters session signals with `MATCH_ARG0_PATH` because the session handle is an object path, and a plain arg0 match never fires.
- `shortcuts.py` uses `org.freedesktop.portal.GlobalShortcuts`. Activated starts, Deactivated stops in push-to-talk mode. `ConfigureShortcuts` needs interface version 2. GNOME 50 answers version 1, so `main.py` shows a dialog and opens Settings › Apps › Utter over `org.gnome.Settings` instead (`--talk-name` in the manifest).
- `injector.py` uses `org.freedesktop.portal.RemoteDesktop` with `persist_mode=2` and stores the restore token in GSettings. GNOME shows the remote control icon in the top bar while a session is open, so the injector closes the session 3 s after each delivery (`CLOSE_DELAY`). Paste mode needs the delay, because the clipboard selection goes away with the session. The next dictation opens a new session with the restore token in about 40 ms and shows no dialog. Typing sends one keysym per character (`keys.key_events()`). A line break is Shift+Return, because Return sends the message in chat apps and in Claude Code. The extension sends the desktop file id of the focused app with `SetTargetApp(s)` when a dictation starts and when the focus changes. `keys.delivery()` pastes text with line breaks into a terminal (`keys.is_terminal()`), because a shell runs Shift+Return as Return, and a terminal always pastes with Ctrl+Shift+V. A bracketed paste keeps the lines in one block. Without the extension, `target_app` is empty and the settings apply. Paste mode uses the Clipboard portal and Ctrl+V. `_send_keys()` sends one key event at a time and waits for each reply. xdg-desktop-portal 1.22 handles each method call in its own thread, so events that are sent together can change places. Mutter then logs `Received multiple virtual 0x.. key releases (ignoring)`, a key or the Shift for a capital letter stays down, and only a new login clears it.
- Audio is captured with `pulsesrc` at 16 kHz mono float32. sherpa-onnx resamples other rates itself. `sounds.py` disconnects the bus handlers of each tone when it ends. The bus holds the closure and the closure holds the pipeline, so before this fix each tone kept its pipeline and 2 file descriptors. After about 250 dictations the process reached the limit of 1024 descriptors: GStreamer logged `gst_poll_get_read_gpollfd: assertion 'set != NULL'`, and the GTK Vulkan renderer failed with `VK_ERROR_OUT_OF_DEVICE_MEMORY`.
- `recognizer.PROVIDER` is `cpu:<path of onnx-cpu.cfg>`. sherpa-onnx reads onnxruntime session options from the file after the colon. `EnableCpuMemArena=0` turns off the CPU memory arena. With the arena, the process kept the memory of the longest decode until it exited: about 10 MB for each second of audio with Parakeet, so 1.5 GB after a 60 s dictation. Without it, the memory goes back after each decode at the same speed.
- The version lives in `src/utter/config.py`. Meson reads it from there. The metainfo has a fixed release history. `build-aux/release/release.py bump X.Y.Z --note ...` sets both, and `release.py check vX.Y.Z` fails in CI when the tag does not match.
- Releases go to a signed Flatpak (OSTree) repository on GitHub Pages: `https://jaydoubleu.github.io/Utter/`, remote name `utter`, branch `stable`, signing key `0AB8199B524EEF94` (private key in the `GPG_PRIVATE_KEY` secret and in `~/.local/share/utter-release/` on Jay's computer). `build-repo.sh` first mirrors the last `HISTORY_DEPTH` (3) commits from the live site with `ostree pull --mirror`, so the new commit has a parent and clients get a static delta. A Pages deploy replaces the whole site, so without the mirror the history is lost. flatpak-builder signs the app commit and `build-update-repo --gpg-sign` signs the AppStream commits and the summary before it makes the deltas. A delta pull does not read the detached signature, so deltas made before the signatures fail with "no signatures found". `verify-repo.sh` proves a signed delta pull. The script deletes the `.Debug` ref, because GitHub Pages allows 1 GB per site. `ostree show --gpg-homedir` reads only `*.gpg` keyrings, not `pubring.kbx`, so the scripts check signatures with a pull and not with `ostree show`.
- All release scripts run in `ghcr.io/flathub-infra/flatpak-github-actions:gnome-50`, in CI and locally through `in-container.sh` (podman). A test of the full release and update path: stage the site with `PAGES_URL=http://127.0.0.1:8765`, serve it with `python3 -m http.server`, and run `verify-install.sh` with `CONTAINER_ARGS="--network=host --env FLATPAK_USER_DIR=..."`. `flatpak-builder --install` names its remote `utter-origin`, the same name as a bundle install, so remove a source build before an install from the repository.

## Commands

```bash
.venv/bin/python -m pytest              # unit tests
.venv/bin/ruff check src tests          # lint
meson setup _build && meson test -C _build   # validates desktop, metainfo and schema
flatpak run org.flatpak.Builder --user --install --force-clean flatpak-build build-aux/flatpak/io.github.jaydoubleu.Utter.yaml
flatpak run io.github.jaydoubleu.Utter
```

## Conventions

- British spelling in prose and UI strings. Code identifiers keep upstream spelling.
- No em-dashes anywhere.
- Keep GTK-free modules GTK-free so tests run in a plain venv.
